# Phased Supervisor Refactor for Mapping Bringup

## Summary
- Refactor the source launch file at [mapping.launch.py](/home/castej-jetson/workspaces/amigo_ros2/src/go2_bringup/launch/mapping.launch.py) into subsystem launch fragments, and add a single `mission_supervisor_node` that owns task mode, posture state, and motion gating.
- Keep current external entrypoints in phase 1 (`mapping.launch.py`, `/voice/command`, the `search` action, and existing voice phrases), but move all actuation and task dispatch out of `voice_command_node` and the follow nodes.

## Implementation Changes
- Split launch orchestration into `mapping_base.launch.py`, `mapping_nav.launch.py`, `mapping_audio.launch.py`, and `mapping_behavior.launch.py`, with shared argument/helper code in `_mapping_common.py`.
- Keep the existing launch profiles `all`, `mission_base`, and `operator_tools`, but group arguments by subsystem and centralize Nav2-derived parameter validation in the shared helper.
- Add `mission_supervisor_node` in `go2_control` with orthogonal FSMs:
  - `task_mode={IDLE,FOLLOW,SEARCH}`
  - `posture_mode={STANDING,LAYING,TRANSITION_TO_STAND,TRANSITION_TO_LAY}`
  - `FAULT` as the terminal safe-state on transition failure/timeouts
- Implement these transition rules in the supervisor:
  - `follow_me`: allowed only from `STANDING + IDLE`
  - `stop_follow`: exits FOLLOW to `IDLE`
  - `search`: from any standing state, preempts FOLLOW, then starts Search
  - `lay_down`: from any state, cancels active task, disables motion, publishes zero motion, then issues `StandDown` and enters `LAYING`
  - `stand_up`: from `LAYING`, issues `StandUp` plus motion-mode recovery, then returns to `IDLE`
  - Illegal requests are rejected with no side effects and are published in supervisor state/events
- Move Search action ownership, Unitree stand/sit requests, motion-mode recovery, cooldowns, and preemption handling into `mission_supervisor_node`.
- Make the supervisor the only authoritative motion publisher:
  - Remap Nav2/search output to `/motion/candidate/nav`
  - Remap person-follow output to `/motion/candidate/follow`
  - Supervisor forwards only the active candidate stream and emits an immediate zero command on every mode exit
- Refactor `person_follow_controller_node` into pure control logic:
  - No direct sport requests
  - No direct mode ownership
  - Publishes candidate twist, controller state, and a “lost target timeout” event
- Refactor `person_follow_vision_node` into pure perception gated by supervisor state instead of raw voice strings.
- Refactor `person_follow_motion_bridge_node` to subscribe to supervisor mode state instead of follow-controller state so the Unitree backend cannot remain active after a posture/task transition.
- Refactor `voice_command_node` into a parser/adapter only:
  - Transcript in
  - Normalized legacy command out
  - No direct Search dispatch
  - No direct `/api/sport/request` publishing
- Extract the supervisor FSM/arbitration logic into a pure Python module such as `mission_supervisor_core.py` so transitions and preemption rules are unit-testable.

## Public API / Interface Changes
- Keep `/voice/command` for phase-1 compatibility, but make the supervisor its only consumer.
- Add `go2_interfaces/msg/RobotModeState.msg` with:
  - `stamp`
  - `transition_id`
  - `task_mode`
  - `posture_mode`
  - `motion_enabled`
  - `source`
  - `detail`
- Add `go2_interfaces/srv/SetRobotMode.srv` with request fields:
  - `task_mode`
  - `posture_mode`
  - `source`
  - `reason`
  - `allow_preempt`
- Add `go2_interfaces/srv/SetRobotMode.srv` response fields:
  - `accepted`
  - `previous_task_mode`
  - `previous_posture_mode`
  - `new_task_mode`
  - `new_posture_mode`
  - `message`

## Test Plan
- Unit-test supervisor transitions for `follow -> lay_down`, `follow -> search`, `search -> lay_down`, `laying -> stand_up -> idle`, illegal transition rejection, and mandatory zero-motion on mode exit.
- Extend follow tests so the controller emits loss events instead of sending sport commands, while preserving the existing follow-control math/state-machine coverage.
- Add integration tests for:
  - `follow_me` then `lay_down`: follow output stops within one control tick, backend disables, supervisor ends in `LAYING`
  - `search` then `follow_me`: Search is canceled before follow becomes active
  - `search` then `lay_down`: Search cancel completes before posture transition, with no further Nav2/follow motion output
- Add launch smoke checks for each fragment and for top-level `mapping.launch.py --show-args`.

## Assumptions
- The editable source of truth is [mapping.launch.py](/home/castej-jetson/workspaces/amigo_ros2/src/go2_bringup/launch/mapping.launch.py); the Trash `install.3/...` copy is a generated artifact.
- Phase 1 keeps ZED, ODAS, Nav2, and SLAM running continuously; robustness comes from logical gating and preemption rather than process lifecycle start/stop.
- Existing voice phrases, the `search` action name, and the `mapping.launch.py` entrypoint remain stable in phase 1; the new typed mode service/state become the long-term control surface.
